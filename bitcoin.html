01 / FIELD NOTES

Bitcoin spends outputs, not a mutable account balance

A wallet’s balance aggregates outputs it can spend.

A transaction consumes existing unspent transaction outputs and creates new outputs with spending conditions. Inputs authorize spending through the relevant script/witness rules. Outputs can pay a recipient and return change to the sender. The fee is the difference between input and output values.

Teaching example: spend a 0.50 BTC output, create 0.20 BTC for a recipient and 0.2999 BTC change; the difference is 0.0001 BTC in fees. These are accounting examples, not current fee quotes. Reusing addresses and combining inputs can expose relationships even though names are not stored in the ledger.

02 / FIELD NOTES

Mining proposes blocks; nodes enforce monetary rules

The reward schedule is not a miner’s discretionary printing right.

Bitcoin’s block subsidy halves every 210,000 blocks under the adopted rules, leading toward a roughly 21 million BTC limit. Miners receive the allowed subsidy plus transaction fees through a coinbase transaction. Nodes reject excess subsidy; fees redistribute existing value rather than creating additional subsidy.

The rules are implemented by software and maintained through network adoption. A fork can propose different rules, but cannot force unchanged validating nodes to accept them. Monetary scarcity is one property; demand, purchasing power and liquidity are separate questions.

03 / FIELD NOTES

Bitcoin is programmable, with a different execution model

Script conditions are not the same as an EVM application.

Bitcoin supports spending conditions such as signature checks and time constraints. Its UTXO model, script rules and transaction validation are distinct from a globally persistent Solidity contract. Learn the exact transaction type and script semantics before translating Ethereum terminology into Bitcoin.

Off-chain payment protocols add their own channel and settlement mechanisms. A transaction shown by an explorer is an observation of that service; a full node validates rules directly. Wallet software may rely on external infrastructure without the user running a node.
