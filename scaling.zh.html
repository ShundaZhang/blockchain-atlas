01 / FIELD NOTES

L2 迁移工作，结算路径决定保障

Ethereum Rollup 与 Bitcoin 支付通道是两种不同扩容模型。

Rollup 执行独立状态机，将数据及状态承诺发布到 Ethereum，由 L1 合约执行特定证明及退出规则。排序器排列交易，Batcher 发布数据，独立节点重建执行。这些职责可以由不同组件承担。排序器的快速回执是早期观察，不自动等于 L1 最终结算。

模型移出 L1 的工作需要检查的条件
Ethereum rollup通用执行与应用状态L1 数据、证明系统、桥及升级权限
Lightning已注资通道参与者之间的更新流动性、最新状态、期限及 Bitcoin 执行
Sidechain / validium独立执行，可能使用独立数据可用性自身验证者或外部 DA 假设，不等同于 Rollup

L2 标签不是完整安全描述。应分开执行正确性、数据可用性、活性及控制权。闪电网络早已部署，后文“近期动向”指持续发展的协议及应用，并不是说支付通道在 2026 年才出现。

02 / FIELD NOTES

Optimistic 与有效性证明采用不同接受规则

状态根是一项承诺，不是状态转换正确的证明。

问题Optimistic Rollup有效性证明 Rollup
提议结果仍可被争议的断言附执行有效性证明的结果
执行约束挑战者质疑错误转换，L1 争议游戏裁定L1 验证器检查特定程序及公开输入的证明
退出时间争议解决及部署特定成熟延迟生成、提交、接受证明及桥条件
其他假设可用数据、按配置规则及时行动的诚实挑战者可靠证明系统、正确电路 / VM、可用数据及正确桥逻辑

交互式故障证明可将执行轨迹收缩到 L1 能检查的争议指令。zkVM / zkEVM 则将所选执行转换为约束并生成简洁证明。Rollup 名称中的“零知识”不意味着交易数据或余额私密。证明建立的是被编码的陈述，不是应用的全部性质。

OP Stack 故障证明桥区分 proveWithdrawalTransaction 与 finalizeWithdrawalTransaction。争议结果、证明成熟时间、额外延迟及 Guardian 权限都重要。不能写死“所有 L2 提现需七天”或“ZK 提现即时完成”。流动性提供方的快速退出还引入自己的定价及交易对手机制。

03 / FIELD NOTES

Blob 与 PeerDAS 扩展数据层，不直接提高 EVM 指令速率

数据可用性与执行有效性回答不同问题。

EIP-4844 引入携带 Blob 的交易：一个 Blob 包含 4096 个域元素，占 131072 字节，并具有独立 Blob Gas 费用市场。EVM 看到的是 Blob 承诺的带版本哈希，不能任意读取 Blob 字节。Rollup 通过该通道发布压缩数据，普通执行 Gas 仍是独立成本。

Blob 可用性是临时的，原始保留窗口约为 18 天，并非永久应用存储。Rollup 节点运营者及归档服务须保存重建所需历史；只有承诺不能恢复丢失数据。

随 Fusaka 部署的 PeerDAS 将 Blob 数据纠删编码成列，节点托管所分配列并采样可用性，不再要求每个节点下载所有完整 Blob。这允许在可控单节点负载下提高容量，但不验证 Rollup 执行，也不让带宽免费。仅改 Blob 参数的升级可调整目标 / 最大数量；它们是协调网络变更，不是自动无限吞吐。

开发流程：选择实际链及测试网络 → 核对 Chain ID 与 RPC → 按其 VM / EVM 支持目标编译 → 部署及检查回执 → 测试桥消息及退出。EVM 兼容可复用熟悉的 Solidity 工具，但预编译、费用核算、交易类型及跨域调用仍可能不同。在链 31337 的 Hardhat 执行不会模拟真实 Rollup 的数据发布或提现合约。

05 / FIELD NOTES

闪电网络在 Bitcoin 上结算可执行通道状态

注资在链上，多数余额更新保留在参与者之间。

支付通道将 Bitcoin 资金交给共同控制的花费规则。双方持有代表可执行状态的签名承诺交易。正常运行交换新承诺并撤销旧状态。在已采用的撤销式设计中，延迟输出及违约补救约束广播被撤销承诺。注资输出持续提供资金基础，参与者不需为每笔支付挖出新 Bitcoin 区块。

Teaching example: capacity = 100,000 sat
Initial: Alice 80,000 | Bob 20,000
Alice pays Bob 15,000
Updated: Alice 65,000 | Bob 35,000
Total capacity remains 100,000 sat

例子刻意省略承诺费用、通道储备、待决 HTLC 及粉尘限制，因此真实可花费能力低于简单总量。协作关闭共同签署结算交易；单边关闭走承诺 / HTLC 执行路径，可能需要等待及额外链上费用。闪电网络改变结算工作的发生时机，不移除底层链。

06 / FIELD NOTES

HTLC 连接多个通道，无需 Alice–Carol 直接通道

价值朝接收方转发，原像向后传递。

Carol 创建随机原像 r，在发票中发布 H=SHA256(r)。Alice 向 Bob 提供一个在期限前揭示 r 才能领取的 HTLC；Bob 向 Carol 提供对应且更早到期的 HTLC。Carol 揭示 r 领取支付，Bob 再将它用于上游。到期时间差为中间节点在链下协作停止时执行权利留出时间。

BOLT 4 洋葱载荷让每跳处理自己的转发指令，路由节点不会得到明文完整路径。但仍可观察邻居及局部时间 / 金额。这是路由隐私，不是通用匿名保证。

BOLT 11 发票可携带支付哈希、金额、有效期及其他路由 / 支付字段。payment_secret 不是秘密原像 r。有效发票不证明存在可用路径，发票有效期也不同于各 HTLC 的链上期限。

07 / FIELD NOTES

流动性方向及运行状态决定可用性

通道容量不是每个方向都能发送的金额。

一个容量 100000 sat、Alice 侧占 80000 的通道不会给 Bob 100000 sat 出站流动性。接收需要对端一侧的入站流动性。Alice → Bob → Carol 路径上，Bob 到 Carol 的通道可能成为瓶颈，即使 Bob 在别处有充足余额。再平衡、兑换、开通道及流动性服务改变分配，也可能增加费用或服务依赖。

非托管运营者须保存最新通道状态并处理执行期限。Watchtower 可在客户端离线期间帮助检测被撤销状态的违约，但不负责支付路由、不保证全部活性，也不替代备份。LND 静态通道备份通过关闭路径支持恢复；恢复种子不同于重建所有通道的最新运行状态。

托管钱包可通过替用户运行通道来隐藏复杂度，但用户此时依赖运营者，而非独立控制这些通道密钥。应将托管关系与服务是否使用 Lightning 分开评估。

08 / FIELD NOTES

在本地 Regtest 拓扑复现支付生命周期

使用真实实现学习，无需公开网络资金。

Polar 使用 Docker 运行 Bitcoin Core 及闪电实现。在本地 Regtest 网络创建三个 LND 节点 Alice、Bob、Carol。通过 Polar 测试注资功能给 Alice、Bob 注资，打开 Alice–Bob 与 Bob–Carol 通道并挖出足够确认。确保两个转发方向具有可花费流动性。打开各节点专用终端，使 RPC / TLS 凭据及端口指向对应节点。

# Carol node terminal — configured local regtest only
lncli --network=regtest addinvoice --amt=10000 --memo="local routing lesson"

# Alice node terminal — paste the returned payment_request
lncli --network=regtest decodepayreq --pay_req="<REGTEST_INVOICE>"
lncli --network=regtest payinvoice "<REGTEST_INVOICE>"

# Inspect each node and the resulting channel balances
lncli --network=regtest listchannels
lncli --network=regtest listpayments

检查解码金额及有效期、支付状态、路径、费用及余额。再在新支付前断开 Bob，或制造出站能力不足，比较失败情况。最后协作关闭测试通道，挖出区块并检查结算输出。记录安装节点版本及协商功能。这是独立 Polar 环境的实验说明；网站及 Hardhat ZIP 不启动或模拟 LND。

09 / FIELD NOTES

桥增加跨系统验证边界

跨边界保留资产身份、消息来源及最终性。

锁定 / 铸造桥在来源链托管资产，在目标链创建表示；其他设计采用销毁 / 铸造或兑换已有流动性。接收合约须验证来源事件、被接受状态及消息。Rollup 官方桥、发行方原生部署及第三方包装资产是不同对象，即使钱包显示相同简称。

检查原因
链 + 精确合约 / 资产 ID符号或熟悉地址不等于跨链资产身份
来源、Nonce 及重放保护有效消息不能授权另一个域或执行两次
最终性及验证机制重组、证明规则、委员会及多签产生不同失效方式
升级权限及退出路径暂停 / 升级桥可改变表示资产的实际控制

跨域调用通常异步。来源交易完成本身不证明目标执行。应设计重试、到期、退款及独立状态跟踪。共享 EVM 或 Rollup 框架不会让独立链变成一个同步原子执行环境。

10 / FIELD NOTES

意图与智能钱包抽象流程，不消除信任条件

互操作正在成为应用接口，同时仍依赖桥机制。

意图指定可接受结果，而不是每个执行步骤。例如以链 A 的 100 单位 X 为代价，在期限前向链 B 交付至少 99 单位 Y。Solver 提供路径或目标流动性，再按订单规则结算。ERC-7683 定义共享跨链订单 / 结算接口，本身不验证所有链，也不保证 Solver 竞争、退款或结算安全。

ERC-4337 加入 UserOperation、Bundler、EntryPoint 及可选 Paymaster。Paymaster 可代付用户 Gas，但仍有人支付且存在代付策略。随 Pectra 部署的 EIP-7702 允许 EOA 持久委托所选代码执行。它不是临时单次调用权限，也不是 ERC-20 授权；执行失败不会自动撤销已处理委托。

这些机制可向用户隐藏切网、重复授权及获取 Gas 的流程，但实现仍须绑定链、接收方、资产、金额、期限及授权，并显示委托 / 恢复权限。“一键”是体验结果，不是新的共识保证。

12 / FIELD NOTES

闪电网络在通道控制、发票及资产方面持续发展

每项新功能都需要对应协议及实现支持。

Splicing 改变通道注资交易以增减容量，同时保留通道关系，不再把每次容量改变都视为无关的关闭 / 重开。BOLT 2 已记录其协商流程；应核对双方版本及功能协商，不能假定所有钱包支持。BOLT 12 Offer 以洋葱消息及盲化路径加入 Offer → 发票请求 → 发票交换流程。Offer 不是简单可复用的 BOLT 11 支付发票。

Taproot Assets 在 Bitcoin Taproot 输出中承诺资产状态，通过额外客户端证明验证资产沿革。识别资产的边缘节点可经 RFQ 报价完成资产 / BTC 转换并使用 BTC 流动性路由，中间 BTC 路由器不必全部实现每种资产。Bitcoin 底层共识仍验证 Bitcoin 交易，不验证发行方的法币储备或每项资产层规则。参与者仍负有资产证明保存 / 验证职责。

2026 年 v0.8 / SDK 发布是该模型的实现进展，不意味着所有稳定币、钱包或路径均可用。多资产支付仍依赖发行方、赎回、定价及边缘流动性。它们扩展支付能力，但没有把 Bitcoin 变成 Ethereum 式通用 EVM。
