02 / FIELD NOTES

A token record is not every right associated with an object

Fungible and non-fungible interfaces represent different state models.

A fungible token tracks interchangeable units; an NFT commonly tracks distinct token IDs and their holders. Metadata or a URI can describe an object without storing the object on-chain. Owning a token does not by itself establish copyright, real-world ownership or permanent availability of linked media.

For an application design, keep asset semantics separate from transport semantics. Who can update metadata, revoke a credential or change an upgradeable contract? These questions remain even when transfers are publicly visible.

03 / FIELD NOTES

Start with the coordination problem

A shared database may be the better engineering choice.

Ask whether participants need independent verification, whether one administrator is acceptable, whether public visibility fits the data, and how mistakes are recovered. Use blockchain where its coordination and trust properties solve the actual problem. Do not add a transferable token only because a project is called Web3.

A good design document states the state-transition rules, authority map, off-chain dependencies, privacy boundaries and exit/recovery mechanisms. Evaluate those separately from fundraising or price narratives.
