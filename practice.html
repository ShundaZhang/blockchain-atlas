Path A · Create the first contract in Remix VM

No browser wallet or real funds are needed for the first run.

StepAction
OpenOpen the original Remix IDE and create MessageBoard.sol
CompilePaste the contract from the Solidity chapter; choose compiler 0.8.30 and EVM target Shanghai
DeploySelect a Remix VM environment, account A and an initial string such as "Hello"
ObserveRead owner/message, call setMessage as A, and inspect the event/receipt
RejectSwitch to account B, try setMessage and confirm rejection with unchanged state

For StudyToken in Remix, replace the npm import with the versioned import below and compile with the same compiler/target. The recipient argument must be a VM account address, not an ENS name or ticker. Read decimals, totalSupply and balanceOf after deployment.

02 / FIELD NOTES

Path B · Run the downloadable local project

Compilation and contract execution have been tested on a local EVM.

Download and extract examples.zip. Use a supported Node.js release (tested here with Node 24.10.0). The lockfile pins the dependencies. Compilation uses local solc; Hardhat supplies the local development node. Open two terminals in the extracted project.

npm ci
npm run compile
# Terminal A
npm run node
# Terminal B
npm test
npm run demo

Expected outcomes: two contracts compile; two test suites pass; the demo prints supply 1,000,000 STUDY, Bob balance 29 STUDY, remaining allowance 6 STUDY, and the changed message. Addresses and transaction hashes vary by run. Scripts accept only loopback chain 31337; no seed phrase or private key is required.

03 / FIELD NOTES

Path C · Understand the public-testnet deployment flow

This is a manual progression after the local checks.

Check current network guidance, then select an application testnet such as Sepolia, a separate test wallet and a suitable faucet/RPC. Obtain test ETH, confirm the chain ID, compile the same pinned source and deploy through a deliberate testnet connection. Inspect constructor arguments, receipt status, address, supply and owner powers.

Publish source and compiler settings for explorer verification where supported; test reads, transfers, approvals and rejection paths with test accounts. Faucets and RPCs may require accounts or impose limits. The provided scripts deliberately do not automate a public deployment or accept production credentials.

Mainnet deployment, distribution, exchange listing and liquidity provision are separate steps with different consequences. A token deployment does not perform them. Keep this learning exercise distinct from a real asset issuance or sale.
