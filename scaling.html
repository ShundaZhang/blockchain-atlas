01 / FIELD NOTES

Scaling relocates work and changes assumptions

Lower fees do not reveal which guarantees remain on L1.

Rollups execute transactions outside L1 and publish specified commitments and data to an L1 verification/settlement path. Optimistic designs rely on a challenge/fault-proof mechanism; validity-proof designs use cryptographic proofs of specified transitions. The exact proof system, data availability and upgrade powers differ by deployment.

A sequencer’s quick receipt is not necessarily the same as L1 final settlement. Ask what happens if the sequencer stops, whether users can reconstruct state, and how withdrawals are enforced. A sidechain with its own validators has a different trust model.

02 / FIELD NOTES

A bridge adds a cross-system verification boundary

The destination token depends on how the source event is recognized.

A common bridge locks an asset on one chain and creates a representation on another. Other designs burn/mint or use liquidity. The receiving system needs a way to verify or trust the source message; validator sets, multisignatures, proofs and upgrade keys create different assumptions.

A wrapped asset with a familiar ticker may not be an issuer-native deployment. Verify the chain, contract, bridge mechanism and redemption route separately. Reorganizations and finality mismatches can complicate message handling across chains.
