部署固定供应 ERC-20 并检查权限

创建固定供应 ERC-20 学习代币授权给予花费方一定权限代币发行流程有多项独立产出
01 / FIELD NOTES

创建固定供应 ERC-20 学习代币

部署合约创建代币状态，不是新建区块链。

// SPDX-License-Identifier: MIT
pragma solidity 0.8.30;

import {ERC20} from "@openzeppelin/contracts/token/ERC20/ERC20.sol";

/// @notice Fixed-supply learning token. No public mint, owner, proxy or sale.
contract StudyToken is ERC20 {
    constructor(address recipient) ERC20("Study Token", "STUDY") {
        _mint(recipient, 1_000_000 * 10 ** uint256(decimals()));
    }
}

StudyToken 继承固定版本 OpenZeppelin ERC20。构造函数向指定接收方铸造 1,000,000 STUDY，显示精度为 18 位。原始供应为 1,000,000 × 10¹⁸ 单位。示例没有加入公开增发、所有者、代理、转账税或销售机制；转账及授权行为来自库。

STUDY 是教学代币名称。部署不会创造担保、需求、价格、交易所上架或流动性。创建代币不同于创建具有自身共识网络的原生币，也不同于运营稳定币发行方。

02 / FIELD NOTES

授权给予花费方一定权限

Approve 本身不转移代币。

balanceOf 记录持有量，transfer 转移调用者代币，approve 设置花费方额度，transferFrom 使用授权转移所有者代币。花费方可以是合约或账户。额度与余额分别检查，大额授权不会创造代币。

例子：授权 10 STUDY，花费方转移 4，普通剩余额度为 6。若所有者只有 3，请求转移 4 仍失败。无限额度及非标准代币需要另行解释。应撤销不再需要的额度，并确认花费方精确合约。

对应资料：ERC-20 standard ↗ · OpenZeppelin token API ↗

03 / FIELD NOTES

代币发行流程有多项独立产出

规格、部署及市场运营是不同工作。

步骤产出
定义规格名称、符号、单位、供应、分配及全部特殊权限
实现与测试固定源码、成功编译及成功 / 失败行为检查
本地 / 测试网部署Chain ID、地址、构造参数、回执及实际供应
公开与验证源码、依赖版本、编译设置及合约身份
如需运营独立分配、流动性及监控计划，部署不会自动完成

真实公开发行中，技术部署只是更广泛金融及运营项目的一部分。本教程以本地 / 测试网工程为边界，不创建销售、资金池或公开募资交易。

对应资料：OpenZeppelin Contracts Wizard ↗ · Smart contract security ↗ · Ethereum networks ↗

检查理解
