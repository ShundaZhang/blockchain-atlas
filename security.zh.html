01 / FIELD NOTES

同时检查代码及特殊权限

许多故障来自对非预期动作的有效执行。

风险机制有用检查
访问控制未授权调用者改变敏感状态逐项特殊函数成功及拒绝测试
重入关键状态尚未确定，外部调用就返回重入分析调用图、状态顺序及适用防护
预言机操纵可操纵或陈旧值驱动经济决定来源、新鲜度、边界及失败处理
授权滥用花费方可转移此前授权代币精确花费方身份、限制权限及撤销
升级控制管理员替换执行逻辑代理 / 管理员图、延时与治理控制

02 / FIELD NOTES

交易排序属于威胁模型

有效交易可能在不同于预期的上下文执行。

公开待处理交易可能在执行前暴露交易计划。排序参与者可在前后插入其他交易，影响池状态或包含。MEV 涉及多种策略与角色，不只是一个合约漏洞。应用需要时应设置明确输出边界及截止时间。

签名、Permit 及账户恢复也需要域分离、Nonce 与过期语义。防重放编码不会让恶意授权变得无害。即使执行确定，前端及 RPC 响应仍是用户决策路径的一部分。

对应资料：MEV ↗ · Ethereum transactions ↗

03 / FIELD NOTES

采用多种验证方式

编译、测试、源码验证及审计回答不同问题。

编译检查语言及代码生成；测试检查选定行为；模糊测试探索输入及不变量；源码验证将公开代码 / 设置连接到部署字节码；审查或审计检查更广逻辑及假设。任何一项都不单独保证全部经济及运营行为。

StudyToken 应检查供应守恒及成功 / 拒绝转账；MessageBoard 应检查所有者权限及拒绝后状态不变。真实金融协议还需扩展至预言机、对抗性组合、治理及事件处置。

对应资料：Smart contract security ↗ · Solidity security considerations ↗
