02 / FIELD NOTES

A read, transaction and contract-to-contract call differ

“No fee to read” does not mean execution has no cost.

An eth_call asks a node to simulate execution without committing state. A transaction requests an included state change and pays gas. A view function called within another transaction still participates in that transaction’s execution cost. ABI data describes an interface; it does not certify honest behavior.

External calls transfer control to other code; that code can call back, fail or consume gas. Follow the entire call chain and update critical state before risky interactions where the design requires it. Events and revert data are useful observations, but check the resulting state too.

03 / FIELD NOTES

Off-chain facts need an explicit oracle path

A contract cannot directly know a price, weather report or legal title.

Oracles publish or deliver external information in a form contracts can consume. Their data source, signer set, update cadence and failure handling become part of application assumptions. A valid oracle signature proves authorization by that signer, not truth of the original measurement.

Randomness, automation and cross-chain messages also need careful input mechanisms. Block fields and current pool prices can be influenced in ways an application author must understand. Avoid treating a deterministic machine as an autonomous source of real-world truth.
