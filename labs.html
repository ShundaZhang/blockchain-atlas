Labs / FIELD GUIDE

Inspect the mechanics
Change one assumption

Three local teaching models. No wallet, public RPC, token transfer, upload or saved exercise input. Hashes use browser SHA-256, not Bitcoin serialization or Ethereum Keccak.

Hash linksToken allowanceAMM quote
01 / HASH LINKS

Relinking a history does not authorize it

Original payload: Alice pays Bob 5. Modify it and compare keeping versus rebuilding the later links. Blocks contain only an index, payload and prior digest.

Ready — choose inputs

With original links, a changed first block breaks the next reference. If all later links are rebuilt, the toy history becomes internally consistent again; no consensus, signatures, difficulty or finality were checked. That distinction explains why a hash chain is not a full blockchain.

02 / ERC-20

Both balance and authorization must permit a transfer

A simplified ordinary finite allowance with no token fees, hooks or special infinite allowance behavior.

Ready — choose inputs

The model computes the resulting owner balance, recipient increase and allowance. Try an amount exceeding allowance, then one exceeding balance. Failures leave all state unchanged. The real downloadable ERC-20 is tested on an EVM; this browser model is not a contract deployment.

03 / DEFI

A swap changes the reserve ratio

A constant-product, v2-style quote with fees retained in the pool. All numbers are synthetic, and the floating-point output is approximate.

Ready — choose inputs

effectiveInput = input × (1 − fee)
output = reserveY × effectiveInput / (reserveX + effectiveInput)
newX = reserveX + input
newY = reserveY − output

If the computed output is below the selected minimum, the model rejects the swap and keeps the original reserves. It does not model other traders, MEV, token rounding, concentrated liquidity or live prices.
